## 2. RT-A items

**A1 Retail profile.** `shop-presets.ts` `RETAIL_KINDS`, `RETAIL_PROFILES`, `applyRetailKind(kind, { registered })`
(business type stays `kirana`; `registered` adds `gst`; explicit `industry_packs`). `retail/rt-profile.ts`
`retailSwitchesFor` / `applyRetailSwitches` write the profile's switches — they only ever turn a check on (a stricter
setting is kept): grocery MRP *warn* + deliveries + short book + free quantity; pharmacy MRP *block* + the same + the 7U
pharma switches (enabled, block expired, block above MRP); general MRP *warn*; electronics cash guard *warn*; jewellery
cash guard *block* + PAN; apparel nothing (C's band GST is per item). `RetailKindPicker` in the setup wizard (under
Kirana / retail) and in Settings → Features ("Custom" clears the profile, packs kept). Landing: `/pos`, jewellery
`/inventory?tab=jewellery&view=rates`. Existing kirana companies are unchanged apart from the checklist step.
Deviation: in Settings → Features the switches apply at once (the settings patch waits for Save).

**A2 MRP guard, GST-cut MRP, relabel queue.** `retail/rt-settings.ts` (object `retail_settings`: `mrp_guard`,
`delivery`, `short_book`, `free_qty`, RT-E's `cash_guard` / `require_pan`; owner only, audited). `retail/rt-mrp.ts`
(pure): price per base unit incl. GST after the line discount and the line's share of an invoice discount
(`pricesPerBaseUnit`), `mrpIssues` (warn → warning; block → error for a clerk, "Sell anyway" confirmation for the owner;
credit notes, quotations and free lines never checked), `mrpAfterRateChange` / `effectiveMrp` (MRP × (100 + new) ÷
(100 + old), only lowers; `until` = stock received up to that day), `basisFromRates` (HSN master default),
`labelPriceNow` / `relabelDue`. `stock-tracking.ts` `liveMrpIssues` (batch MRP from the stock events, else the
catalogue MRP, each with its basis) runs inside `liveDocTrackingIssues` after `saleLimitGate` (a line the pharma option
already refused is not reported twice — the stricter applies), and directly from the POS / editor save when the
company has no batch / serial / godown tracking (the old path skipped the checks entirely there). The owner's override
is audited once after the confirmed save (`rt-settings.ts` `recordMrpOverrides`, POS and editor). POS shows the live
message in its retail strip; the editor shows a warning toast at save. `pricing.ts` `mrpLessRate` starts from the
effective MRP. Inventory → Summary: "Labels to reprint" (`RelabelQueue`, opens the existing label sheet preselected) and
the GST-cut tool (also on Batches) — `rt-mrp-store.ts` `setMrpBasis` (stock item + catalogue row), `stampLabelsPrinted`
(the label sheet stamps `label_printed_at` + `label_price` on print). Settings → Items → *Retail checks*
(`RetailChecks`). Deviation: the basis is per item with an `until` day (batches received up to it), not stored per batch.

**A3 Home delivery and rider cash.** `retail/rt-delivery.ts`: the `delivery` snapshot (address, phone, slot, rider,
status new → packed → out → delivered | returned | cancelled, charge, COD), `moveDelivery` (delivered + COD records the
balance as a Cash receipt dated the delivery day and tagged `rider_id`; "Cash with riders" ledger, Cash & bank group,
created on first use), `settleRider` (journal Dr Cash counted / Cr Cash with riders expected, a shortage / excess to a
ledger the user must pick; `rider_settlements` row), `returnedCreditNote` (goods-returned credit note via
`documents.createCreditNote`), `cashWithRiders`. COD cash really moved — it is **not** a `movedNoCash` row: the ledger
posts it to "Cash with riders" (`ledger/postings.ts`), Tally / the receipts CSV name that ledger, the Z report keeps it
out of the drawer (`riderCash`, CSV line) and the Z modal shows "Cash with riders" outstanding; shift totals carry
`rider_cash`. Cash readers see the money once (Today: the COD receipt; Books: the settlement moves it into Cash).
UI: POS retail strip (Delivery switch, address, rider, COD, a delivery charge line at the goods' rate), editor summary
`DeliveryStrip`, Receivables → Deliveries (board by status, rider filter, run sheet print, `wa.me` "out for delivery",
riders master, settlement). Deviation: a delivery bill is numbered when saved (the POS saves it as *packed*); moving an
editor draft from *new* to *packed* does not issue it.

**A4 Free quantity and discount; short book.** `PurchaseLine.free_qty` (+ the typed `discount_percent`):
`purchase-normalize.ts` `readPurchaseLines` returns `quantity` = paid + free (what the stock engine, batches, serials and
landed cost receive), `unitCost` = taxable ÷ (paid + free) (10 + 1 at ₹80 less 5% → ₹69.09; `quantity × unitCost` is
still the taxable value), plus `paidQty`, `freeQty`, `netRate`. Header GST / ITC readers are unchanged (value only);
`purchases.ts` `computePurchaseTotals` now applies the line discount. The party-rate hint keeps the rate per paid unit.
Bill line editor: *Free* and *Disc %* cells (Retail checks "Free quantity", or a bill that already has them); the
serial count on a bill = paid + free. Purchase returns: paid units go back first at cost, free units at zero value (a
note says how many); a return of free units only cannot be saved (zero value). Short book: `retail/rt-short-book.ts`
(`short_book` rows, `lastSuppliers` through the purchases contract, `groupBySupplier`, `makePurchaseOrders` — one PO per
last supplier, "Supplier to be chosen" for unknown items, rows marked *ordered*; `arrivedRows` / `closeShortBook`;
`backInStockLink`). Inventory → Short book (`ShortBookTab`) and "Not found? Add … to the short book" in the POS retail
strip (from the search text).

## 4. Round 9 changes that touch existing CA items (RT-A)

- RT4: no sale above MRP is now available to every shop (off by default; profiles set warn / block); GST-cut MRP only
  lowers.
- RT5: free goods carry no value and no GST; ITC on the paid value only.
- RT6: a delivery charge is billed at the goods' rate and HSN (part of their value, as G5).
